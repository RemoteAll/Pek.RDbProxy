## 2026-10-23（六）日志目录为什么不存在：任何执行都留痕

**用户原话**

> 另外为什么没有日志目录？我记得这种默认都会有日志目录的。只要有执行过

**根因**

- `dhrust::logs` 的文件日志是**惰性建目录**的（写线程要打开当日文件时才 `create_dir_all`），而 `-init` / `-status` / `-token` / `-install` 这些纯文本命令此前**一条日志都不写**（只有 `run_command` 里的启动/请求日志才写）→ 程序目录里根本没有 `Log/`。
- 另一处隐患：`main` 结尾 `std::process::exit(code)` 前没有 flush，异步队列里最后几条日志会丢。

**改动**

1. `init_console_and_file` 之后立刻落一条 `Pek.RDbProxy v… 执行：args=[…] 程序目录=…` 并 `flush` —— **只要执行过就一定有 `Log/yyyy_MM_dd.log`**。
2. `main` 退出前统一 `dhrust::logs::flush()`（对齐"exit 前不 flush 会丢最后日志"的既有教训）。
3. `-install / -uninstall / -start / -stop / -restart` 成功/失败写日志（服务模式下没有控制台，只能靠文件事后追溯）。
4. `run_command` 的「读取配置失败 / 启动失败 / 监听失败」补 `error!`（此前只有 `eprintln`，服务模式直接丢失）。
5. `-status` 末行打印日志目录、当日文件名与**最近 3 行**（`dhrust::io::latest_file_by_ext` + `read_tail`）。
6. README 新增「日志」章节（文件名 / 10MB 拆分 / 保留 200 / 行格式 / flush / 不可写介质表现），FAQ Q3 排障第一步改为看日志。

**验证**

- 临时目录执行 `-status`：生成 `Log/2026_10_23.log`，内容 `19:56:48.330 01 N - Pek.RDbProxy v0.1.5 执行：args=["-status"] 程序目录=…`（文件头 4 行 + 行格式与 DH.NCore 一致）。
- `-init` 后 `-status` 输出 `日志：…\Log（2026_10_23.log）` + 最近 3 行。
- `cargo test --offline`：lib 12 + `proxy_e2e` 2 全绿；`cargo clippy --all-targets` 0 告警。

## 2026-10-23（五）字段级安全（表管理 / 列策略）+ 执行策略 FAQ

**用户原话**

> 先帮我把下面的问题的处理结果放到Readme.md中（PowerShell 执行策略禁止运行脚本，先上方案，后验证）
>
> 另外肯定有场景是有些值的字段再怎么样因为安全问题是不允许返回的，但是可能使用者或者ORM拿数据是会默认请求所有的字段的

**决策**

- 按 **数据源 + 列名** 登记 `allow` / `mask` / `deny`，两种模式：`audit`（学习，默认）/ `enforce`（拦截）。
  - 粒度取列名而非表名：SQL 里表名可能带别名/子查询/联表，可靠解析代价高；列名是结果集里天然存在、且真正决定"这个字段要不要给出去"的东西。
- **`deny` 是硬拒绝**：与模式无关，`audit` 模式也不返回 —— 给"绝对不能出去"的字段（密码、密钥、手机号）。
- 被拦截列在结果里**直接消失**（不是返回空值）：ORM 按列名取值得到"字段不存在"，比空值安全（空值会与真实 NULL 混淆）。
- 未登记列：`audit` 放行并记审计「未登记字段」；`enforce` 不返回 —— 给"先跑一段时间观察，再收紧"的落地路径。
- **元数据接口（GetTables / GetSchema）不受约束**，只约束 Query 的数据行。
- `mask` 当前实现与 `deny` 同样"不返回该列"（保留枚举值，便于将来做值替换）。

**实现**

- `src/policy.rs`：`Mode` / `Action` / `Rule` / `Policy`（`decide(db,column) -> (Action, 是否登记)`）+ `UnknownFields`（每库上限 200 条观测）+ `load/save/path_of`（`Config/field-policy.json`，原子写）。
- `src/proxy.rs`：`apply_field_policy(db, RowSet)` 接在 `/Db/Query` 回包前（剪列 + 写审计「字段已拦截：a,b；未登记字段：c,d」）；`policy_snapshot / save_policy / unknown_fields`。
- `src/panel.rs`：`GET /api/fields`（mode + rules + unknown）、`POST /api/fields`（upsert）、`POST /api/fields/delete`、`POST /api/fields/mode`。
- 下沉 Pek.RCode：`RowSet::project(&[usize])`（列名与每行值同步裁剪）—— 提交 `d731423`，已推 main。
- README：新增「字段级安全」章节；FAQ 新增 **Q1b 执行策略**（`-ExecutionPolicy Bypass -File` / `-Scope Process` / `-Scope CurrentUser RemoteSigned` / 组策略受限时改走 `-init`/`-install`/`-RegisterAgent` 手动等价路径）。

**待办**

- 面板「表管理」UI 未做（后端与 HTTP 协议已就绪）。
- `onUnconfigured`（未配置字段默认 `error`）与**表级三态**口径待用户拍板（原话："是不是整个表没有安排过就允许，安排过就可以返回，但是如果一个字段都没有做备注或者做某种安全配置，那么就只能返回字段的空值等等"）。

## 2026-10-23（四）写盘加密 + 在线升级 + 部署脚本

**用户原话**

> 可以的，而且这个有没有安装到RAgent的脚本？等你处理好后我就要安装部署了
>
> 我需要在线升级的，另外dist中的要过滤
>
> 类似于这种描述需要改么？（指出「真实连接串只保存在本机 Config/Proxy.toml」与加密事实不符）

**改动**

1. **连接串写盘加密**：`Config/Proxy.toml` 里的 `Connection` 一律存 `enc:v1:`（AES-256-GCM），密钥 `Config/.key`（Unix 0600，`PEK_RDBPROXY_KEY` 可覆盖）。
   - 新增 `proxy::ensure_key` / `encrypt_connection` / `Proxy::migrate_encrypt`；**启动时自动把仍是明文的连接串加密写回**（幂等）。
   - 内存 `section.connection` 保持磁盘形态，`source_connection()` 解密后给面板回填 —— 面板看到明文、磁盘只有密文。
2. **在线升级**：新增 `POST /api/upgrade`（鉴权 + 64MB 上限 + PE/ELF 头校验）→ 写 `Update/` → 由既有 10 秒热检测原子替换并重启；设置页新增「⬆ 在线升级」卡片。
   - 实测：上传 25,768,448 字节 → 日志 `18:11:18 收到在线升级包` → `18:11:33 自升级完成…准备重启`，进程随后退出。
3. **TLS 改 rustls**：`pek-rcode` 特性由 `tls-native` 换成 `tls-rustls`，否则 Linux 交叉要静态 OpenSSL（`openssl-sys` 构建失败）；Windows 行为不变，交叉产物纯净。
4. **部署脚本**：
   - `scripts/install.ps1`（Windows，UTF-8 with BOM）：停旧服务 → 复制 → `-init` → `-install`/`-start` → 可选 `-RegisterAgent`。
   - `scripts/install.sh`（Linux）：同上，检测到 `/www/Agent|/www/Stardust/Agent|/opt/StarAgent` 的 `StarAgent.config` 就自动注册星尘。
   - `scripts/pack.ps1`：默认补丁版本 +1；Windows release + Linux musl x64/arm64（zig 交叉）；产物 `dist/*.zip|tar.gz` + `SHA256SUMS`。
5. **`.gitignore` 过滤 `dist/`**（另含 `*.zip`/`*.tar.gz`），打包产物不入库。

**坑**

- PowerShell **变量名不能与参数同名（不区分大小写）**：`$targets` 撞上 `[ValidateSet]$Targets` → `ValidateSetFailure`；改名 `$linuxTargets`。
- zig 在本机是 `G:\Tools\zig\zig-0.17.0`，脚本查找顺序补上 `G:\Tools\zig`（原先只有 `E:\Soft`）。
- Git 的 `tar.exe` 需要 `C:\Program Files\Git\usr\bin` 在 PATH 里才能找到 gzip，否则报 `gzip: command not found` + `Broken pipe`。
- `-SkipBuild:$false` 这种写法在 `-File` 方式下会触发参数转换错误，switch 直接写 `-SkipBuild`。

6. **数据源增删改** → `RwLock<Registry>` + 配置写回（`apply_type_fixes` + `sync_array_of_tables` + `backup_and_write`，**保留模板注释**）；同名替换保留统计。
7. **服务化** → `dhrust::service::ServiceManager`；CLI `-install/-uninstall/-start/-stop/-restart/-status`。
8. **星尘托管** → `dhrust::staragent::register`；CLI `-RegisterAgent`。
9. **自升级** → `Update/` 目录热检测（10s 静置 + 原子替换 + 退出重启），与 RAgent 同机制。
10. **接续基建** → `.github/copilot-instructions.md`、`docs/项目接续指南.md`、`docs/用户档案.md`、`tools/continuity/`（含模板与自检脚本）、`.vscode/tasks.json`（打开项目自检）。

**踩坑记录**

- **`/Db` 必须加进 WAF 白名单**，否则 `SELECT * FROM` 会被 SQLi 特征拦截 —— 安全护栏交给 `is_read_only_sql`。
- **`Jwt::from_secret` 要求 `算法:密钥`**（`HS256:hex`），裸 hex 会报错 → `normalize_jwt_secret`。
- **配置写回必须 `merge_missing_keys`**：`apply_type_fixes` 只改已存在的键，**新增字段（如 `WebPasswordHash`）不会写入文件** —— 否则每次启动都重新初始化账号、JWT 密钥每次变。
- **`route` 返回 `HttpOutcome`**，需 `HttpOutcome::Response(...)` 包装。
- **`guard` 闭包生命周期问题** → 改用函数指针 `fn(&Proxy, &Ctx) -> HttpResponse`。
- Windows 路径进 JSON 需正斜杠（`\U` 非法转义）—— 测试里 `.replace('\\', "/")`。

**验证**

- `cargo test --offline`：lib 9 + `proxy_e2e` 2 全绿。
- `cargo clippy --all-targets --offline`：0 告警。
- 浏览器实测：免登录（LocalOnly + 回环）→ 概览卡片（含「编辑/解除只读/删除」）→ 编辑对话框（连接串/令牌 placeholder「留空 = 不改」+ 备注回填 + 只读勾选）。

## 2026-10-23（一）项目创建：数据库调试代理（防凭据外泄）

**用户原话**

> 另外是不是可以写一个Rust版本的数据库代理工具…帮我在Rust项目中新起一个项目用于数据库调试

**决策**

- 新项目 `Pek.RDbProxy`（crate `pek-rdbproxy`），独立仓库 `github.com/RemoteAll/Pek.RDbProxy`。
- **核心动机**：把真实数据库凭据收敛在一台机器上，项目侧只拿到 `Server=http://内网地址;Database=<Name>;Password=<Token>;provider=network` —— 凭据不出内网、不进代码仓库。
- 协议：复用 Pek.RCode `provider=network`（`DbClient`）契约，`/Db/*` 成功返回**裸** `{data:…}` / `{DbType,Version}` / 数组，失败 `{code,msg}`（**不能用面板的 `{ok,data}` 信封**）。
- 数据源来自 `Config/Proxy.toml` 的 `[[Databases]]`（Name/Connection/Token/ReadOnly/Description），支持 `enc:v1:` 加密连接串。
- 只读护栏在服务端 `is_read_only_sql` 兜底（防注入绕过）。
