## 2026-10-28（二十）桌面工具加「工作区」：连接按项目保存 + SQL 片段 + 执行历史

**用户原话**

> 工具上要能把每一次连接的数据库链接按项目保存起来，可以直接点击进去再执行sql吧，
> 而且也可以把执行过的sql也保存下来，也可以删除掉某些sql，对于保存的sql可以进行备注命名方便复用等等，
> 这些提高人性化操作方便的你要考虑到，也要帮我实现我没有考虑到的

**做了什么**

| 能力 | 说明 |
|---|---|
| 连接（按项目分组） | 名称 / 项目 / 代理地址 / 数据源名 / 令牌 / 备注；单击选中、双击直接连；健康点显示上次连接成败与时间 |
| SQL 片段 | 命名 + 备注 + 可绑定连接；单击填入、双击直接执行；按使用次数排序；可改/删 |
| 执行历史 | 用**保存的连接**执行后自动记录（SQL / 成败 / 行数 / 耗时 / 连接名）；同连接同 SQL 只留最新，上限 200；可「存为片段」、删单条、清空 |
| 草稿 | 每个连接各存一份 SQL 草稿（localStorage），切换连接不丢 |
| 导入 / 导出 | JSON；导出含明文令牌（界面醒目提示），导入按「名称 + 数据源」合并 |
| 结果与报告 | 查询结果可复制 CSV / JSON；自检报告可一键复制 |

**用户没提、我补的几点**

1. **令牌加密落盘**：`dhrust::secret`（AES-256-GCM）+ 本机 `.key`；界面只显示掩码，
   **令牌不下发到前端**——前端只传连接 id，Rust 侧解密后直接发请求。
2. **连接健康状态**：列表圆点 + 顶栏「上次连接成功/失败 + 时间」，一眼看出哪个连接坏了。
3. **双击即连 / 双击即跑**：单击选中、双击执行，减少点按次数。
4. **快捷键**：`Ctrl+Enter` 查询、`Ctrl+Shift+Enter` 执行写语句、`Ctrl+K` 搜索、`Ctrl+L` 连接测试、`Ctrl+S` 存片段。
5. **写语句二次确认**：非查询操作先确认，避免误点。
6. **临时连接**：不落盘、不记历史，方便一次性排查。

**改动**

- `desktop/core/src/store.rs`（新增）：`Store` + 数据模型 + 视图（令牌掩码）+ 导入导出；
  损坏文件自动备份为 `workspace.json.bad-<时间>` 并以空工作区启动。

- `desktop/ui/*`：布局重构为「左栏工作区 + 右栏执行区 + 通用对话框」。
- `desktop/core/examples/ws_seed.rs`：开发用示例数据。

## 2026-10-28（十九）审计里看得见实际 SQL：备注/错误不再顶掉 SQL

**用户原话**

> 看不到实际请求的sql语句吗？

**根因**

`record(..., error)` 的最后一个入参被当成两种语义：查询成功时传的是「字段策略备注」
（`字段已拦截：1；未登记字段：1`），失败时才是真错误；而面板渲染写的是
`r.error || r.sql` —— 备注一非空，SQL 就被盖掉了。

**改法**

- `AuditEntry` 新增 `note` 字段：`record` 里按 `ok` 分流——成功进 `note`、失败进 `error`，两者互不占用。
  API `/api/audit` 同时返回 `sql` / `note` / `error`。
- 面板「SQL 审计」表头改为「SQL（备注 / 错误）」：**SQL 始终显示**（带 title 悬浮全文），
  备注一行小字（琥珀色，前缀「备注：」）、错误一行小字（红色，前缀「错误：」）。
- 行数为 -1（未知行数）显示为 `—`，不再出现 `-1`。
- 日志同步：成功且有备注时输出 `… sql=… note=…`。

**验证**

- 协议回放：`Query SELECT 1 AS One` → 审计 `sql="SELECT 1 AS One"`、
  `note="字段已拦截：One；未登记字段：One"`；`Query SELECT Id, Name FROM t`（表不存在）→
  `error="数据库错误：no such table: t"` 且 `sql` 依旧完整。
- 面板实测（127.0.0.1:5599）：两行分别展示 SQL + 备注 / SQL + 错误，Login 显示 `—`。
- 回归：21 单测 + 5 e2e（新增断言：审计必须同时含实际 SQL 与 note）全绿。

## 2026-10-28（十八）双击即用：首次运行自动生成配置模板

**用户原话**

> 这个怎么打开就退出了

> 这个还不能直接双击运行吗？

**事实（日志实证）**

`dist/pek-rdbproxy-v0.1.16-win-x64/Log/2026_10_28.log`：

```
20:26:45.915 读取配置失败：配置文件不存在：…\Config/Proxy.toml（先运行 `pek-rdbproxy -init` 生成模板）
```

目录里只有 `install.ps1` / `pek-rdbproxy.exe` / `README.md` / `Log`，**没有 `Config`** ——
`run_command` 读配置失败 → `return 1` → 双击的控制台窗口一闪而过，用户只看到「打开就退出」。

**改法**

- `run_command(base, interactive)`：`interactive` = 无参数启动（双击/直接执行）。
  此时若 `Config/Proxy.toml` 不存在 → **自动写出模板并继续启动**，并在控制台打印
  「首次运行：已生成配置模板 …（示例数据源 demo，只读）」。
- **服务 / `-run` / `-s` 仍是「配置就绪才运行」的守卫**（`interactive=false` 不自动生成），
  避免 SCM 或星尘托管拿占位配置反复拉起。
- 启动后交互模式额外打印：面板地址 + 「关闭此窗口 = 停止代理；长期运行用 `-install` 或 `-RegisterAgent`」。
- `config::load` 的缺失提示改为「直接双击运行会自动生成模板，或运行 `pek-rdbproxy -init`」。

**验证（空目录 + 无参数，模拟双击）**

```
目录：Config/ Data/ Log/ Update/ pek-rdbproxy.exe
输出：首次运行：已生成配置模板 …\Config/Proxy.toml
      已启动：http://127.0.0.1:5599   /  面板：http://127.0.0.1:5599/
      关闭此窗口 = 停止代理；长期运行请用 -install 装为系统服务，或 -RegisterAgent 交给星尘托管。
HTTP GET /api/status → 200（长度 535）；监听 127.0.0.1:5599
```

**排查时踩到的两个环境坑（写下来避免重复）**

1. 终端里残留 `$env:PEK_RDBPROXY_BASE` 会让「空目录双击测试」实际跑在旧基目录上，
   看起来像「改了没生效」；测试前先 `Remove-Item Env:PEK_RDBPROXY_BASE`。
2. 终端里残留 `$env:CARGO_TARGET_DIR`（之前为绕开 G 盘空间不足设过）会让 `cargo build`
   把 exe 写到别处，仓内 `target/debug` 里的还是旧文件；**验证前先确认产物时间戳**。

## 2026-10-28（十六）驱动组件改为按需下载（`driver-pack`），升级不必重编代理

**用户原话**

> 这里是不是后面驱动组件有更新，这里都不会更新的？不能做成其他项目那样按需自动下载么？

**问题（确认属实）**

`Cargo.toml` 里的 `driver-*` 特性是**编译期**决定：

- 新库类型（Oracle / 达梦 / MongoDB / HANA / Firebird / ODBC…）不加特性就用不了，必须改 `Cargo.toml` 重编；
- 驱动 crate（mysql / postgres / tiberius…）版本由 Pek.RCode 的 `Cargo.toml` + 锁文件决定，升级同样要重编重发；
- 现场已部署的二进制更不会自己变。

**做法（照搬生态既有实现，不另起一套）**

`Pek.RCode` 早已有 `driver-pack`（`DriverManager`），消费方是 `HLZX.EIP/src/drivers.rs` 与
`HlktechIoT/.../hlktech-iot-core/src/drivers.rs`。本次把 Pek.RDbProxy 也接上：

| 位置 | 改动 |
|---|---|
| `Cargo.toml` | 加 `driver-pack` 特性（其余 `driver-*` 保持不变，作为内置兜底） |
| 新增 `src/drivers.rs` | 进程级驱动管理器：`prepare` / `report` / `install` / 缓存扫描；复用 `driver_pack::{StoreConfig, DriverManager}` |
| `src/config.rs` | 新增 `[DriverStore]`（`Url`/`PubKey`/`CaFile`/`ComponentFirst`/`CacheDir`），默认 `ComponentFirst=false` |
| `src/proxy.rs` | `open_source` 开头过 `drivers::prepare`；`update_driver_store` 保存后重建管理器并重开全部数据源 |
| 面板 | 设置页新增「🧩 驱动组件」：组件清单（内置/本地版本/最新版本/运行中）+ 安装·升级 + 组件源配置；`GET /api/drivers`、`POST /api/drivers/install`、`POST /api/drivers/config` |
| `-status` | 增加一行「驱动组件：组件源/内置/组件优先/缓存」 |

**取驱动顺序**：本机组件缓存 → 内置驱动（零网络）→ 联网按需下载。

- `ComponentFirst=false`（默认）：内置类型零网络直连；本机已缓存该组件时改用组件；未内置类型按需下载。
- `ComponentFirst=true`：连内置类型也强制走组件（驱动完全随组件源单独升级）。
- 打开数据源用 `DriverManager::ensure`（**缓存优先**），不是 `ensure_updated`——避免每次重启/打开数据源都联网拉目录（资源与带宽口径）。

**实测（本机，临时基目录 + 127.0.0.1:5598）**

- `-status`：`驱动组件：组件源=off（内置 mysql, postgresql, sqlserver；组件优先=false；缓存 Data/Drivers）`
- `GET /api/drivers`（`Url=off`）：`offline=true`、`items=[]`、`builtinProviders` 正确
- `POST /api/drivers/config`：写回 `Config/Proxy.toml` 的 `[DriverStore]`（保留注释），数据源自动重开
- 离线安装 `dbserver-oracle`：返回可操作错误（提示补 `Url` 或把驱动包解压到缓存目录）
- 切回默认组件源：`https://p.sc8.fun` 可达，列出 **12** 个组件、最新 `0.1.3`、`mysql/sqlserver/postgresql` 正确标注「内置」
- `POST /api/drivers/install {id:"dbserver-mysql"}`：**0.4s** 完成下载+校验+解压到 `Data/Drivers/dbserver-mysql/0.1.3/dbserver.exe`，面板显示「已就绪」

**回归**：`cargo test` 20 单测 + 5 e2e 全绿；`cargo clippy --all-targets` 零告警。

**顺带**：`Pek.RCode` 的 `DbClient`/`http` 增加可选 `User-Agent`（`with_user_agent` + `post_json_ua`/`post_bytes_ua`/`get_text_ua`），
用于桌面工具等机器客户端——服务端 WAF 打开 `block_empty_ua` 时不会被拦。

## 2026-10-23（十五）provider=network 到底能不能用：两端实测

**用户原话**

> **`provider=network`** 是真的可以吗？你有验证过么？

**实测 2：C#（新增 `tools/csharp-network-check`）**

## 2026-10-23（十四）字段清单改为「按数据源 + 来自实际请求」

**用户原话**

> 字段不是应该默认根据请求返回的字段来么？而且也是应该和数据源关联的

**现状（本来就有的行为）**

- 字段观测确实来自**实际请求**：`apply_field_policy` 每次查询把"未登记列"记入 `UnknownFields`（按数据源分组，每库上限 200 条）。
- 策略规则本身也带数据源：`Rule { db, column, action, note }`。

**问题（呈现方式）**

- 面板把"规则"和"未登记字段"平铺成两张全库表，看起来不像"和数据源关联"；
- 已登记的列仍残留在「未登记字段」列表里（`UnknownFields` 只在"当前未登记"时记录，但历史快照不清），容易误以为没生效。

**改动**

1. 后端 `GET /api/fields`：`unknown` 返回前**剔除已登记列**（按 `db + column` 大小写不敏感匹配）。
2. 前端「🛡 字段安全」改为**按数据源分组**：每个数据源一张卡片，显示
   `N 条规则` + 该库「未登记字段（含出现次数）」+ 「一键允许未登记列（n）」（调 `POST /api/fields/bulk`）。
   数据源已删除时卡片标红提示；规则按数据源过滤后只在该卡片内展示。
3. 新增/编辑规则的弹窗：列名输入加 `datalist`，候选 = **该数据源请求返回过的列 + 已登记列**（可下拉选，也可手填）；
   数据源切换时刷新候选。
4. 每行快速登记从两项（允许/拒绝）扩为三项（**允许 / 拒绝 / 掩码**）。

**验证（本机实测）**

- 对 `demo` 跑一次 `SELECT 1 AS id, 'alice' AS name, '13800000000' AS mobile`；
- `/api/fields` 返回 `db=demo columns=id,mobile,name`，`mode=enforce`，日志 `字段已拦截：id,name,mobile；未登记字段：id,name,mobile`；
- 面板出现 `🗄 demo  0 条规则  一键允许未登记列（3）` 与三行未登记列；
- 点「一键允许未登记列」→ `demo：已登记 3 个列`，规则表出现 3 条 `allow`，未登记列表清空（`unknown: {}`）。

`cargo test`：15 单测 + 4 端到端全绿；`clippy` 0 告警。

## 2026-10-23（七）服务装不上 / 停不下来（1053）与首次默认密码

**用户原话**

> 这是没有安装成功吧
>
> 这个和DH.Deploy的模式不一样吗？我看我在windows上安装Dh.Deploy的RUst版本很正常啊。

**现象**

- `install.ps1` 输出 `服务 install 失败：服务已存在：PekRDbProxy` → `-start` 报
  `StartService FAILED 1053`（服务未及时响应启动请求）。
- 随后 `-uninstall` 报"成功"但服务仍是 **Running**、exe 仍被占用，`-reinstall` 报"服务已存在"。
- 日志里还有一条：`面板账号初始化失败：密码至少 10 位`。

**根因**

1. **服务不响应停止（主因）**：`run_as_service("PekRDbProxy", || {}, run)` 的 `on_stop` 是**空闭包**，且主循环是 `loop { sleep(3600s) }` —— SCM 发 Stop 后进程永不退出。
   - 直接后果：`sc stop` 只能超时；`sc delete` 变成"标记删除"，**旧进程继续占着 5599**。
   - 对新实例：端口被占 → `Listener::bind` 失败 → 启动即退出 → SCM 判定超时 → **1053**；注册项若还是旧参数（缺 `-s`）也会同样 1053。
   - 这与 DHDeploy/RAgent 是**同一套 `dhrust::service` 模式**，差别只在这两个项目都会监听停止信号（`SHUTDOWN`）再退出——RDbProxy 抄漏了。
2. **`dhrust` 卸载过于宽松**：`uninstall` 只在 Running 时尝试 stop、错误被 `let _ =` 吞掉、`sc delete` 后不等待 SCM 真正移除；`reinstall` 又吞掉卸载错误 → "以为重装了，实际注册项还是旧的"。
3. **首次默认密码被强度规则拒绝**：初始化走 `update_server`，`password_strength("admin")` 不通过 → 首启后**根本没有可用密码**（面板登录不了）。

**修复**

1. `main.rs`：新增 `static SHUTDOWN: AtomicBool`，服务分支传真实 `on_stop`；主循环改 200ms 轮询 `SHUTDOWN` → 退出时关监听 + `logs::flush()`。
2. `DH.RustBase/src/service/windows.rs`：`uninstall` **不论状态先 stop**，等 `STOPPED`（20s）失败直接报错；`sc delete` 后轮询等 SCM 真正移除（15s）；`reinstall` 不再吞卸载错误（归属冲突可见）。
3. RDbProxy 新增 `-reinstall` 命令；`install.ps1` 检测到旧服务自动 `-reinstall`，失败时打印 `sc qc`（BIN_PATH 应带 `-s`）与日志尾，并区分"程序没起来（无日志）"。
4. `Proxy::ensure_default_account()`：**故意绕过强度校验**写入 `admin/admin`（首启一次性，登录成功即 `upgrade_weak_password` 换成强密码并只展示一次）。

## 2026-10-23（六）日志目录为什么不存在：任何执行都留痕

2. `main` 退出前统一 `dhrust::logs::flush()`（对齐"exit 前不 flush 会丢最后日志"的既有教训）。
3. `-install / -uninstall / -start / -stop / -restart` 成功/失败写日志（服务模式下没有控制台，只能靠文件事后追溯）。
4. `run_command` 的「读取配置失败 / 启动失败 / 监听失败」补 `error!`（此前只有 `eprintln`，服务模式直接丢失）。

6. README 新增「日志」章节（文件名 / 10MB 拆分 / 保留 200 / 行格式 / flush / 不可写介质表现），FAQ Q3 排障第一步改为看日志。

> 另外肯定有场景是有些值的字段再怎么样因为安全问题是不允许返回的，但是可能使用者或者ORM拿数据是会默认请求所有的字段的

**决策**

- 按 **数据源 + 列名** 登记 `allow` / `mask` / `deny`，两种模式：`audit`（学习，默认）/ `enforce`（拦截）。
  - 粒度取列名而非表名：SQL 里表名可能带别名/子查询/联表，可靠解析代价高；列名是结果集里天然存在、且真正决定"这个字段要不要给出去"的东西。
- **`deny` 是硬拒绝**：与模式无关，`audit` 模式也不返回 —— 给"绝对不能出去"的字段（密码、密钥、手机号）。
- 被拦截列在结果里**直接消失**（不是返回空值）：ORM 按列名取值得到"字段不存在"，比空值安全（空值会与真实 NULL 混淆）。
- 未登记列：`audit` 放行并记审计「未登记字段」；`enforce` 不返回 —— 给"先跑一段时间观察，再收紧"的落地路径。
- **元数据接口（GetTables / GetSchema）不受约束**，只约束 Query 的数据行。
- `mask` 当前实现与 `deny` 同样"不返回该列"（保留枚举值，便于将来做值替换）。

**实现**

- `src/policy.rs`：`Mode` / `Action` / `Rule` / `Policy`（`decide(db,column) -> (Action, 是否登记)`）+ `UnknownFields`（每库上限 200 条观测）+ `load/save/path_of`（`Config/field-policy.json`，原子写）。
- `src/proxy.rs`：`apply_field_policy(db, RowSet)` 接在 `/Db/Query` 回包前（剪列 + 写审计「字段已拦截：a,b；未登记字段：c,d」）；`policy_snapshot / save_policy / unknown_fields`。
- `src/panel.rs`：`GET /api/fields`（mode + rules + unknown）、`POST /api/fields`（upsert）、`POST /api/fields/delete`、`POST /api/fields/mode`。
- 下沉 Pek.RCode：`RowSet::project(&[usize])`（列名与每行值同步裁剪）—— 提交 `d731423`，已推 main。
- README：新增「字段级安全」章节；FAQ 新增 **Q1b 执行策略**（`-ExecutionPolicy Bypass -File` / `-Scope Process` / `-Scope CurrentUser RemoteSigned` / 组策略受限时改走 `-init`/`-install`/`-RegisterAgent` 手动等价路径）。

**待办**

- 面板「表管理」UI 未做（后端与 HTTP 协议已就绪）。
- `onUnconfigured`（未配置字段默认 `error`）与**表级三态**口径待用户拍板（原话："是不是整个表没有安排过就允许，安排过就可以返回，但是如果一个字段都没有做备注或者做某种安全配置，那么就只能返回字段的空值等等"）。

## 2026-10-23（一）项目创建：数据库调试代理（防凭据外泄）

**用户原话**

> 另外是不是可以写一个Rust版本的数据库代理工具…帮我在Rust项目中新起一个项目用于数据库调试

**决策**

- 新项目 `Pek.RDbProxy`（crate `pek-rdbproxy`），独立仓库 `github.com/RemoteAll/Pek.RDbProxy`。
- **核心动机**：把真实数据库凭据收敛在一台机器上，项目侧只拿到 `Server=http://内网地址;Database=<Name>;Password=<Token>;provider=network` —— 凭据不出内网、不进代码仓库。
- 协议：复用 Pek.RCode `provider=network`（`DbClient`）契约，`/Db/*` 成功返回**裸** `{data:…}` / `{DbType,Version}` / 数组，失败 `{code,msg}`（**不能用面板的 `{ok,data}` 信封**）。
- 数据源来自 `Config/Proxy.toml` 的 `[[Databases]]`（Name/Connection/Token/ReadOnly/Description），支持 `enc:v1:` 加密连接串。
- 只读护栏在服务端 `is_read_only_sql` 兜底（防注入绕过）。
